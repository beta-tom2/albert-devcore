# Albert DevCore roadmap

## v0.1 - Working foundation

- [x] environment doctor and safe project adoption;
- [x] repository map, session context, routing, and prompt packets;
- [x] bounded read-only Ollama runner and local diff review;
- [x] Windows PowerShell 5.1 and zero-paid-API policy.

## v0.2 - Context and repair memory

- [x] change-aware import and test maps;
- [x] repair history and similar-fix search;
- [x] Heat Map, Knowledge Graph, Fix DNA, Night Audit, and handoff;
- [x] ADOS as the single preparation entry point.

## v0.3 - Efficient and evidence-driven ADOS

- [x] Incremental Hash Index and Symbol Index;
- [x] Elastic Context budgets;
- [x] Error Fingerprinting, Regression Memory, ADR Memory, and Negative Memory;
- [x] Log Compressor, Scope Guard, Verification Ladder, and Evidence Gate;
- [x] ATLAS, NAVIRA, BPMN Studio, and generic project adapters;
- [x] Checkpoint/Resume, Queue Engine, and read-only Night Mode;
- [x] local usage analytics and deterministic A/B benchmark;
- [x] PowerShell 5.1 integration smoke test.
- [x] Windows PowerShell 5.1 CI for parser, smoke, and clean-worktree verification.

## Next

- [x] bounded compiler-backed reference resolution when a project already provides local TypeScript;
- [x] optional, preview-first Windows Task Scheduler management for Night Mode with explicit install and uninstall confirmation;
- [x] project-owned health thresholds and bounded local trend baselines;
- [x] richer test-to-symbol association for monorepos with bounded focused-test execution;
- [x] PR evidence summary generated from the local Evidence Gate artifacts, with repository-state freshness validation.

No roadmap item may require a paid third-party AI API. Ollama remains read-only, and protected work continues to require Codex-level review.

## v0.4 - Autonomous and approval-aware execution

- [x] single-task queue leases with stale-lease recovery and bounded retries;
- [x] central route enforcement for deterministic, Ollama, and Codex work;
- [x] bounded read-only Ollama first pass only after an explicit manual route;
- [x] generated Codex handoff with exact completion and release commands;
- [x] Draft-PR-only background-agent contract with protected-domain stops;
- [ ] revalidate configured project schedules against the accepted runtime revision after promotion.

## Reliability follow-up

- [x] read-only status for actual runtime, installed core file hashes, lineage and existing Windows schedules;
- [x] explicit checkpoint freshness states without promoting old verification evidence;
- [x] MANUAL_ONLY enforcement in the dispatcher route, including negative prefix cases;
- [x] shared skill contract and task-local behavioral scenario definitions;
- [ ] record independent behavior observations for the candidate and active clients;
- [ ] promote the reviewed candidate and verify the canonical scheduled runtime.

Checked code capabilities do not imply that a schedule, publisher, external
provider or cloud worker is installed or currently active. Deployment state is
established from actual configuration and recent results.
