# Подключение и наследование: что именно настраивается

Этот документ предназначен для получателя после первоначальной оценки. Он описывает варианты подключения; наличие документа в архиве не является командой менять ваши настройки.

## 1. Доступность, выбор и память — три разных уровня

**Доступность навыков.** В локальном Codex пользовательская папка `~/.agents/skills` предназначена для навыков, применимых к разным репозиториям. Установка в `.agents/skills` внутри проекта ограничивает размещение этим проектом и его подходящими подпапками.

**Выбор навыка.** Codex и ChatGPT могут выбирать навыки по описанию задачи. Дополнительная запись в глобальных инструкциях делает ожидаемый порядок работы явным: для подходящих задач сначала прочитать Router, затем выбрать нужных специалистов. Это инструкция агенту, а не отдельный процесс, отслеживающий каждую новую папку на компьютере.

**Память проекта.** У каждого проекта свои идентификатор, репозиторий, источники, checkpoint и решения. Общий набор навыков не должен превращать их в общую неразличимую память. Настройка `.ados/state-export.json` требует настоящих значений для конкретного проекта.

Источники: [Build skills](https://learn.chatgpt.com/docs/build-skills), [контракт Project State](../ADOS_PROJECT_STATE.md), [DevCore adoption](../../scripts/adopt-albert-project.ps1).

## 2. Оценка в обычном ChatGPT

Можно передать архив и [задание на оценку](REVIEW_PROMPT_RU.md) в доступный вам чат. Если этот клиент способен читать вложения, помощник сможет анализировать инструкции и структуру пакета. Если архив не раскрывается, передайте описание и выбранные `SKILL.md` отдельными файлами.

Загрузка файлов для анализа не равна постоянной установке навыка. Она не меняет все будущие чаты, не выдаёт доступ к GitHub и не устанавливает программы на ваш компьютер. Доступный способ постоянного подключения нужно проверить в вашем клиенте и аккаунте.

В поддерживаемой среде ChatGPT Skills можно импортировать выбранные личные навыки штатным способом. Для общего распространяемого пакета из нескольких навыков документация рекомендует plugins. Этот комплект ещё не опубликован как устанавливаемый plugin в каталоге.

Для облачных подключений пользователь авторизует собственные аккаунты отдельно. Файлы отправителя не переносят его подключения, подписки или разрешения. Источник: [Skill controls](https://learn.chatgpt.com/docs/enterprise/skills).

## 3. Первый локальный пилот в Codex

Сначала выберите небольшой отдельный Git-проект для проверки. Прочитайте действующий `AGENTS.md` и сохраните его ограничения. Не ставьте вторую копию одноимённого навыка глобально и локально без необходимости: это создаёт лишнюю неоднозначность выбора.

Для Windows в архиве есть исходный [установщик](../../scripts/install-albert-dev-skills.ps1). Его следует выполнять из распакованной версии этого комплекта, а не из случайной другой копии DevCore. Пусть `$devCoreRoot` и `$projectRoot` содержат фактические абсолютные пути к этим папкам.

Предварительная проверка размещения в одном проекте:

```powershell
powershell.exe -NoProfile -File "$devCoreRoot\scripts\install-albert-dev-skills.ps1" -ProjectPath $projectRoot -DryRun
```

После решения об установке:

```powershell
powershell.exe -NoProfile -File "$devCoreRoot\scripts\install-albert-dev-skills.ps1" -ProjectPath $projectRoot
```

Для распространения на проекты текущего пользователя используются соответственно `-Global -DryRun`, затем `-Global`. По умолчанию этот установщик переносит только три собственных проверенных навыка. Внешние специалисты из каталога им не загружаются.

Установщик сверяет файловые манифесты и прекращает операцию при отличающихся существующих копиях. Сначала сравните и сохраните эти копии; не удаляйте их ради обхода проверки. Если проверенная установка не отражается в интерфейсе, обновите список Skills либо откройте новую рабочую сессию и проверьте обнаружение по имени.

На macOS/Linux сами текстовые навыки можно разместить штатным способом подходящего клиента. Windows-скрипты DevCore/ADOS нельзя считать проверенными для другой среды только потому, что `SKILL.md` читается. Проверки опубликованной версии проводились под Windows PowerShell 5.1; отдельное подтверждение переносимости runtime требуется по месту.

## 4. Пример глобального правила для будущих проектов

После проверки совместимости добавьте этот фрагмент к существующим общим инструкциям вашего Codex. Он не заменяет остальные правила и сам ничего не исполняет.

```markdown
## Общие навыки и настройка проектов

- Для существенных задач разработки, отладки, дизайна, архитектуры,
  проверки, статуса проекта и передачи работы используй доступный
  albert-skill-router. Простые задачи оставляй простыми.
- Выбирай минимальный полезный набор доступных специалистов. Соблюдай
  инструкции платформы, поставленную пользователем задачу и правила
  конкретного проекта. Не устанавливай недостающие пакеты самовольно.
- При явной задаче создать или подключить новый проект один раз проверь,
  какие правила, память и bootstrap уже существуют. Используй проверенную
  версию DevCore, сохраняй существующие файлы и добавляй только необходимое.
- Храни память по проектам: настоящий projectId, репозиторий, видимость,
  разрешённые источники и checkpoint. Не копируй состояние другого проекта.
- Запрос анализа или статуса не разрешает менять настройки. Публикация,
  фоновые службы и внешние AI-провайдеры настраиваются отдельно.
```

Так новое задание получает общий порядок работы без ручного перечисления навыков. Проверка того, что конкретный клиент читает эти инструкции и видит установленные навыки, остаётся частью первоначальной настройки.

## 5. Когда подключать DevCore/ADOS и память

Если полезны только design/architecture routing, runtime можно не подключать. Если нужны checkpoints и экспорт состояния, отдельно изучите [README](../../README.md) и [Project State](../ADOS_PROJECT_STATE.md), затем используйте имеющийся adoption flow в согласованном проекте.

`adopt-albert-project.ps1` — операция записи, а не dry run. Она может зарегистрировать путь проекта и создать локальный контекст и исключения Git. Существующий `AGENTS.md` сохраняется через Copy-IfMissing: недостающий фрагмент маршрутизации в нём нужно согласованно добавить, а не ожидать автоматического слияния текста.

Этот bootstrap не создаёт готовую конфигурацию экспорта памяти за любой проект. Укажите уникальный ID, действительный GitHub origin и видимость, явный список отслеживаемых документов. При неизвестных значениях оставьте настройку незавершённой; не подставляйте чужой репозиторий или private/public наугад.

Экспорт сохраняет метаданные и хеши исходных документов. Он не выполняет автоматически fetch/commit/push и не заменяет резервные копии. При публикации нужно проверить получателя и содержимое. Для нескольких исполнителей сначала используйте одного ответственного за общее состояние; синхронизация файлов не обеспечивает блокировку.

## 6. Минимальная проверка пользы

На одной реальной небольшой задаче проверьте:

- выбран ли подходящий специалист и пропущены ли ненужные;
- сохранены ли правила и терминология вашего проекта;
- подтверждён ли результат подходящим тестом или наблюдением;
- может ли другой сеанс восстановить задачу, незавершённое и следующий шаг;
- осталось ли меньше повторного чтения и исправлений, чем в вашем обычном процессе.

Если выигрыш не подтверждается, уменьшите набор или откажитесь от лишнего слоя. Универсальная установка всех 33 дополнительных специалистов не является целью.
